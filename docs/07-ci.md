# 07 CI

Everything in this repository ends up running on my server, so a typo in a
playbook or a leaked key is a real problem. Every change to `main` now goes
through a pull request, and GitHub Actions has to pass before it can be
merged.

## Checks

The workflow is [`.github/workflows/ci.yml`](../.github/workflows/ci.yml). It
runs on every pull request and on every push to `main`. Each check is a
separate job, so they run in parallel and show up as separate statuses.

| Job | What it checks | Config |
|-----|----------------|--------|
| `yamllint` | Syntax and formatting of every YAML file: Ansible, Compose, Home Assistant, the workflow itself | [`.yamllint`](../.yamllint) |
| `ansible-lint` | Playbook syntax and Ansible best practices, `production` profile | [`ansible/.ansible-lint`](../ansible/.ansible-lint) |
| `pytest (3.12)`, `pytest (3.13)` | Unit tests for [`tools/ssh-report`](../tools/ssh-report/) | |
| `gitleaks` | Secrets anywhere in the Git history | |

A full run takes about two minutes. Most of that is `ansible-lint`
downloading the collections.

## Decisions

**Tool versions are pinned.** `yamllint`, `ansible-lint` and `pytest` are
pinned in [`requirements-ci.txt`](../requirements-ci.txt). A new release of
`ansible-lint` often adds rules, and I do not want CI to turn red on a day
when I did not change anything. Upgrades should come as their own pull
requests.

**Collections are declared.** The playbooks use modules from
`community.general`, `community.docker` and `ansible.posix`. They are listed
in [`ansible/requirements.yml`](../ansible/requirements.yml). Before CI they
were only installed on my WSL machine by accident. A clean runner made that
obvious, because `ansible-lint` could not find the modules.

**yamllint rules.** The config extends the default rule set with a few
changes. `document-start` is off because most of my files do not start with `---`.
`line-length` is 160 instead of 80. `truthy` does not check keys, because
GitHub Actions uses `on:` as a key. `ignore-from-file: .gitignore` keeps it
out of the collections that `ansible-lint` installs into `ansible/.ansible/`.

**pytest on two Python versions.** docker01 runs Ubuntu 24.04 (Python 3.12)
and pve runs Debian 13 (Python 3.13). `ssh_report.py` runs on both, so the
tests run on both.

**gitleaks without the GitHub Action.** The job downloads a fixed gitleaks
release and checks its SHA256 before running it. That is three lines of
shell that I can read, instead of third-party action code running in my
workflow. It scans the full history (`fetch-depth: 0`), because a secret that
was committed and later deleted is still in Git. `--redact` keeps any finding
out of the job log, which is public for this repository. Before adding the job
I ran it locally against all 41 commits and it found nothing.

**Workflow token is read-only.** `permissions: contents: read` at the top of
the workflow. None of the jobs need to write anything.

## Branch protection

`main` is protected with a repository ruleset. The ruleset is stored in
[`.github/rulesets/main.json`](../.github/rulesets/main.json) and was created
with the GitHub API:

```bash
gh api -X POST repos/ralferik/homelab/rulesets --input .github/rulesets/main.json
```

Rules:

- changes only through a pull request (no approvals required, I work alone)
- all five CI jobs must pass, and the branch must be up to date with `main`
- the required checks must come from GitHub Actions (`integration_id`
  15368), so a status set some other way through the API does not count
- squash merge only, linear history
- no force push, no branch deletion
- no bypass, also not for me as the admin

Merged branches are deleted automatically (`gh repo edit
--delete-branch-on-merge`).

To check that it works, I made an empty commit on `main` and pushed it:

```
remote: error: GH013: Repository rule violations found for refs/heads/main.
remote: - Changes must be made through a pull request.
remote: - 5 of 5 required status checks are expected.
 ! [remote rejected] main -> main (push declined due to repository rule violations)
```

If I change the JSON file, I apply it again with `PUT` to
`repos/ralferik/homelab/rulesets/<id>`.

## Workflow

```bash
git switch -c some-change
# edit, commit
git push -u origin some-change
gh pr create --fill
gh pr checks --watch
gh pr merge --squash --delete-branch
git switch main && git pull
```

To run the same checks locally before pushing:

```bash
yamllint .
cd ansible && ansible-lint
cd tools/ssh-report && python3 -m pytest -v
```

[`.editorconfig`](../.editorconfig) sets LF line endings, a final newline and
no trailing spaces, which were the most common yamllint errors when I set
this up.
